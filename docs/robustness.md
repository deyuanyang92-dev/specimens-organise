# 稳健性与数据安全（v0.10.42 起）

本软件长期使用、数据不可再生。本文记录**已有的防线**、**出事后怎么恢复**、**维护时必须遵守的纪律**。
做法参考：SQLite 原子提交、Zotero 自动备份、Office AutoRecover / VS Code Hot Exit、
3-2-1 备份原则、Go / npm / pip 对 Windows 文件占用的重试、基于 Inno Setup 的静默升级。

## 一、防闪退

| 防线 | 位置 | 说明 |
|---|---|---|
| 文件被占用自动重试 | `table_backend.retry_on_file_lock` | 杀毒 / 网盘同步 / Excel / 刚写完的文件会被短暂占用；所有 xlsx 读取和原子替换退避重试 5 次（约 1.5 s） |
| 读失败用上次数据 | `ExcelStore._cached_rows` | 重试仍失败：只读界面先用上次读到的数据；**写操作绝不用旧数据**（防覆盖） |
| 界面刷新失败不退出 | `ui._on_store_op_done`、`_report_recovered_error` | 记日志（`crash_*.log`，Context=recovered）+ 状态栏提示 |
| 切换编号读失败不错乱 | `ui.select_voucher` | 先读后切换；失败停在原编号，编辑仍正常保存 |
| 全局异常钩子 | `ui._install_qt_exception_dialog` | 主线程异常弹窗不退出；工作线程异常只经信号交给主线程显示（工作线程碰 Qt 控件会原生崩溃） |
| 原生崩溃记录 | `boot_guard.enable_fault_log` | 段错误 / 访问违例的栈写入 `boot_fault.log` |
| 卡死探针 | `ui_watchdog` | 界面卡住 > 2 s 写 `gui_stall_*.log` |

## 二、防丢数据

| 防线 | 说明 |
|---|---|
| 原子写 | 所有数据文件：临时文件 → 校验能重新打开 → 原子替换；`settings.json` 同样，并保留 `.bak` |
| 未保存修改日志 | 每次编辑立即记入本机 `recovery/`；落盘后删除。崩溃 / 断电 / 保存失败后下次打开工作区提示恢复（帮助 → 恢复未保存的修改…） |
| 每日自动备份 | 每个工作区每天第一次打开：工作区 `数据/数据版本/` 一份 + 本机一份，各留最近 14 天；手动 / 导入前 / 回退前快照永不自动删除。本机副本位置在 **设置 → 每日备份位置** 修改（默认 `%APPDATA%\标本入库管理\backups\`，在 C 盘；建议改到非系统盘、且不是工作区所在的盘）。改位置后旧位置里的备份仍可用于恢复 |
| 危险操作前快照 | 导入、回退、批量撤销、合并前自动快照 |
| 工作区锁 + 心跳 | 一个工作区同时只允许一个写入者；切换工作区后心跳跟随新工作区 |

## 三、出事后怎么恢复

1. **刚才的修改没了** → 帮助 → 恢复未保存的修改…
2. **数据被改坏 / 误删** → 版本管理里选一个快照回退（回退前会自动再做一份「回退前快照」，可反悔）。
3. **工作区所在的盘坏了 / 文件夹被删** → 新建空工作区后，帮助 → 从本机备份恢复数据…
4. **软件打不开** → `%APPDATA%\标本入库管理\startup_failure_*.log`、`boot_fault.log` 发给维护者。
5. **闪退 / 卡死** → 帮助 → 打开崩溃日志目录，把最新的 `crash_*.log` / `gui_stall_*.log` 发给维护者
   （先看日志开头的 `Version:` 和 `Time:` 是不是这一次）。

## 四、升级

- 默认**启动时检查更新**（每 24 小时最多一次），有新版顶部黄条提示。
- 点「立即升级」：下载安装器并**强制校验 sha256** → 提示「立即重启更新」→ 软件正常关闭（先保存）→
  后台静默安装 → 自动重新打开。失败则重新打开旧版，并在下次启动说明原因与安装日志位置。
- 便携版（zip 解压使用）仍走旧的下载 + 切换流程。

## 五、维护纪律（发布前必须满足）

1. **测试先行**：修 bug 先写能复现的测试，确认失败，再修到通过。
2. **CI 门禁**：每次推送都在 **Windows + Linux** 上跑全量测试（`.github/workflows/ci.yml`）；
   发布（推 `v*` 标签）先跑同一套测试，**不过不打包、不发布**。
3. **测试隔离**：`scripts/run_tests.py --isolate` 每个测试文件一个进程，单用例 180 s 看门狗——
   卡住会打印所有线程的调用栈并失败，而不是挂到超时。
4. **Windows 专属坑**（2026-10-04 首次在 Windows 跑全量时暴露）：
   打开的文件不能删 / 改名（测试里用完的 store 要 `close()`）；临时目录可能是 8.3 短名；
   任何会弹模态框 / 系统框的代码，在测试里都必须替换掉或设 `SPECIMEN_NO_SYSTEM_DIALOGS=1`。
5. **打包后试跑**：发布流程会真实启动打包好的 exe（`--smoke`），失败不发布。
